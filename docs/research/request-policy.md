# ListenBrainz request policy

Snapshot: 2026-09-25. Project-specific API permission allows behavior comparable to the official clients, provided requests remain selective, intentional, and free of lifecycle or retry storms. The audited reference heads matched upstream at Android/KMP `3a0e4eff249cb52b9369d150e3210679294f8362` and iOS `a0eb10444ba9af5a8408355c63b1405ad7b447d5`.

## Official-client findings

| Concern | Official Android/KMP | Official iOS |
|---|---|---|
| Global request rate/concurrency gate | None found | None found |
| HTTP 429 | Typed error; no automatic retry or `Retry-After` replay | No dedicated handling found |
| History/feed | Bounded Paging sources cached in view-model scope | `isLoading`/end guards and fixed pages |
| Search | 500 ms debounce, duplicate suppression, per-query/type cache | 500 ms debounce and duplicate suppression |
| Artwork | Cache plus concurrency limit of two for playlist covers | In-memory `NSCache` |
| Playing Now | One initial read followed by lifecycle-owned WebSocket updates | Ordinary HTTP reads |
| Dashboard/stats | Independent requests without a global gate | Broad concurrent fan-out on appearance |

The useful precedent is not unbounded traffic. It is endpoint-specific intent: bounded pages, debounced search, cache reuse, limited artwork work, and realtime updates instead of polling.

## Brainz request policy

The tested replacement is active. It deliberately separates reads from mutations:

1. at most two independent ListenBrainz reads may run at once;
2. identical in-flight reads coalesce only when credential scope, endpoint, and shaped wire parameters match exactly;
3. cancelled final waiters cancel queued work and reserve an already-started request key until its transport drains;
4. feature-level guards remain in place: bounded history/feed pages, debounced cancellable search, cached one-shot profile/stat loads, and no lifecycle-owned polling loops;
5. an HTTP 429 reset defers both lanes globally, while the original failure is surfaced without automatic replay;
6. mutations remain on one serialized lane with a one-second minimum interval and are never retried automatically;
7. DEBUG/test telemetry records only a closed endpoint category, lifecycle, coalesced-waiter count, and in-flight count—never request identity, token, parameters, headers, error descriptions, or response payload;
8. credential-derived scopes are process-local HMAC values. Raw tokens are never placed in request keys, telemetry, or cache keys.
9. Year in Music makes one aggregate read only after a year is opened or selected. Frozen 2021–2024 reports use an empty-token client, an anonymous 24-hour cache, cancellation on selection replacement, and a 16 MiB receive/decode ceiling; no archive, artwork, or ranking row is preloaded.
10. External service actions resolve only already-loaded canonical `mbid_mapping.url_rels`, then fall back to submitted `spotify_id` and `origin_url`. Resolution, provider de-duplication, and canonicalization are local: opening the menu performs zero ListenBrainz, MusicBrainz, provider-search, or playback-resolution requests. Only exact streaming/free-streaming relationship types and strict canonical HTTPS destinations are accepted. Listen payloads inspect at most 32 relationship rows, expose at most one destination per supported service and eight total actions, and reject listens/Playing Now response bodies above generous 4 MiB/1 MiB ceilings before decoding.
11. Artist Detail shares the current website/official KMP `POST /artist/{mbid}/` payload between its cover/identity, community totals, top listeners, Popular Tracks, Releases, and Similar Artists. Its bounded positive/absent/failed cache is the only owner of that read; the response is decoded once and its cache state is published inside the coalesced operation before the request key drains. A failed cache entry remains an error for the page-owned explicit retry while child sections suppress duplicate messages. Switching/expansion is local, row hydration is forbidden, and the authenticated artist-popularity and entity-listener endpoints remain available for explicit standalone consumers but are not automatic fallbacks on this page.
12. Whole-playlist deletion performs one fresh, non-coalesced canonical owner read immediately before one serialized POST. A protected token-free account/playlist digest barrier is durably synced before gate admission. There is no automatic retry or post-success poll; only an explicit later **Check again** action may make one new read to determine whether the playlist still exists. The barrier survives ambiguous transport, malformed success, server failure, post-admission cancellation, and relaunch, and it clears only after confirmed absence/success has evicted relevant caches.
13. A CritiqueBrainz entity summary performs one exact anonymous `limit=5` read through its dedicated gate, exact-request coalescing, and five-minute cache. Opening the full-text reader passes the decoded value through navigation and performs zero requests; it does not paginate or claim to represent every published review.
14. Active History search filters only the current in-memory latest/day snapshot and its latest-mode Playing Now value. It performs zero ListenBrainz or MusicBrainz provider, pagination, refresh, or metadata-hydration requests. Paging belongs to one stable sentinel keyed only to the raw latest/day tail, so typing or clearing a query cannot recreate it; newly visible rows may still perform their ordinary artwork loading.
15. Playlist reordering is a one-move editor with zero requests on open, drag, reset, or cancel. A normal save makes exactly three intentional ListenBrainz calls: one fresh non-coalesced full-order preflight, one serialized no-retry move POST, and one fresh non-coalesced full-order postflight. A definite `400` or `429` stops after preflight plus POST; `403` spends one fresh visibility read; `401`/`404` purge without another read. A live ambiguous response gets at most one postflight, while post-admission cancellation leaves the durable barrier for explicit review. Removal and reorder share one opaque account/playlist mutation barrier, so another scene cannot issue a competing positional change.
16. Opening Listen Details makes zero requests. Explicitly opening **Find MusicBrainz match** starts the current prefilled query after the existing debounce; later edits cancel superseded work, so only the current query may issue one independently gated MusicBrainz recording search. Selecting a result makes no request. **Save match** sends exactly one serialized, no-auto-retry ListenBrainz manual-mapping POST using the listen's recording MSID and the selected canonical recording MBID. The flow performs no `get_manual_mapping` read, polling, post-success refresh, or background replay. Cancellation before gate admission sends nothing; an indeterminate post-admission outcome remains visible across candidate changes and requires a separately confirmed explicit resend.
17. The Album collage composer reads only canonical release MBIDs already present in the loaded top-album snapshot. Its draft candidates intentionally omit remote artwork URLs, so opening it, choosing or ordering covers, changing presentation options, and dismissing are network-free. **Create** freezes one exact request and admits one anonymous `POST /1/art/grid/` through the coalescing read lane; success or expected absence may enter the bounded 24-hour exact-request cache. There is no automatic generation, option-change request, retry, metadata hydration, Cover Art Archive thumbnail request, or postflight. An explicit retry is a new user action using the same immutable request.
18. Opening playlist collaborator search makes no request. A settled username query waits 500 ms and may make one authenticated user-search GET; normalized repeats use the screen cache, identical live reads coalesce, and query changes cancel both scheduled work and an in-flight explicit retry. Add/remove actions stay local. Save performs one fresh non-coalesced metadata preflight, at most one serialized no-retry full-snapshot edit POST, then the existing canonical reconciliation read after confirmed success. A stale preflight makes no POST, and an indeterminate mutation cannot be replayed automatically.

This is intentionally stricter than copying the official clients' unconstrained fan-out. The conditional API allowance is used for selective concurrency, while coalescing, pagination guards, cancellation, caching, shared 429 deferral, and tests prevent erroneous traffic. Any future retry or concurrency increase requires endpoint-specific evidence and new tests first.

The documented artist-ranked popularity GETs are not the mobile default. Current server `e83a7ab` requires a token, exposes no `count` or pagination parameter, and returns every matching entity. Reusing the already-required combined artist-page response also replaces the page's separate artist popularity and all-time top-listener reads, removing two redundant requests without adding a fallback fan-out.
